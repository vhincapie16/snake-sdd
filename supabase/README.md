# Persistencia HU-005 (KAN-5)

La CLI está fijada en `package-lock.json`. Estos comandos se ejecutan desde la raíz del worktree; no necesitan Docker para el proyecto remoto.

1. Ejecutar `npx --no-install supabase login` e introducir el token directamente en el terminal o completar la autenticación en el navegador. No compartirlo en el chat.
2. Configurar en `.env.local`, ignorado por Git, solo `SUPABASE_URL` y `SUPABASE_SERVICE_ROLE_KEY`. Obtener la clave privilegiada del proyecto de pruebas y pegarla en el editor local; nunca usar `NEXT_PUBLIC_*`. La contraseña PostgreSQL y el token de la CLI no son variables de la aplicación.
3. Ejecutar `npx --no-install supabase link --project-ref <referencia-del-proyecto-de-pruebas>`. Si se solicita contraseña PostgreSQL, introducirla en el terminal, sin escribirla como argumento.
4. Revisar `npx --no-install supabase db push --linked --dry-run --skip-vault` y detenerse para autorización humana antes de aplicar migraciones. No usar `--include-seed` ni `--include-roles`.

La migración propuesta crea únicamente `public.game_results`, sus restricciones, índice de ranking y permisos: RLS habilitado, sin acceso público y con `SELECT`/`INSERT` para el servidor. No actualiza ni elimina resultados. El dry-run enumera migraciones; no demuestra que el SQL se haya aplicado ni que exista persistencia real.

`seed.sql` contiene 15 resultados ficticios con empates por puntuación, fecha y UUID. Es una semilla local; su ejecución remota requiere autorización separada. No ejecutar resets remotos. No se ha iniciado Docker ni se ha ejecutado esta semilla.
